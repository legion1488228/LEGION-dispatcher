# ЛЕГИОН — Диспетчерская (Telegram Mini App)

Рабочая Mini App только для владельца и помощников. Агентам, бригадирам и обычным
сотрудникам приложение не показывается — они продолжают пользоваться Telegram-ботом и группами.

## Что уже реализовано

### Заказы по датам

- отдельные «папки» по датам;
- агент может прислать заказ за 2–3 дня и он сразу появляется в нужной дате;
- фильтр `Все / Частные / ГБУ`;
- статусы `Новый / В расстановке / Состав готов / Отправлен бригадиру / Закрыт`;
- сортировка заказов по времени выдачи.

### Расстановка бригад

- бригадир назначается одной кнопкой;
- показываются только бригадиры со статусом `готов` на выбранную дату;
- заказ на 4 человека = бригадир + 3 сотрудника;
- заказ на 6 человек = бригадир + 5 сотрудников;
- состав выбирается галочками;
- все четыре группы сотрудников доступны вместе;
- первыми показываются сотрудники ±2 см от роста бригадира;
- рядом видны группа, рост и 🚗;
- каждому человеку разрешено максимум 2 заказа за день;
- `0/2`, `1/2`, `2/2` видны прямо при выборе;
- при `2/2` сотрудник заблокирован;
- два помощника могут расставлять разные заказы одновременно; PostgreSQL блокирует конфликтующие назначения;
- есть `Снять состав` с подтверждением.

### Отправка бригадиру и агенту

- заказ не отправляется бригадиру, пока состав не собран полностью;
- после `Состав готов` Mini App сама пишет бригадиру;
- бригадир закрывает заказ через текущего бота и указывает время связи утром;
- только после этого бот автоматически отправляет агенту ФИО, телефон бригадира и время связи.

### База сотрудников

В разделе `Сотрудники` есть массовый импорт списка. Это важно: чтобы считать
`Не отписался`, Mini App должна заранее знать полный активный состав, а не только тех, кто написал `готов`.

Формат одной строки:

```text
ФИО; группа; рост; авто; телефон; Telegram ID
```

Например:

```text
Иван Иванов; основной; 186; авто; +79990000000; 123456789
```

### Готовность сотрудников

Четыре группы:

1. Бригадиры
2. Основной состав
3. Безнал состав
4. Резерв

Статусы:

- `Готов`
- `Не готов`
- `Выходной`
- `Не отписался`

Mini App отдельно показывает:

- сколько готово **на официальном срезе 15:30**;
- сколько готово сейчас;
- кто не отписался к 15:30;
- разбивку по всем четырём группам.

Если человек отписался после 15:30, он может использоваться в реальной расстановке,
но официальный показатель 15:30 не переписывается задним числом.

### ГБУ

- отдельный источник заказа `ГБУ`;
- импорт фотографии таблицы через OCR (Tesseract rus+eng);
- приложение показывает распознанный текст и черновики;
- помощник проверяет дату, время, ФИО, категорию, количество и маршрут перед сохранением;
- OCR специально не сохраняет заказы без проверки пользователя.

### Готовые формы агентов

API умеет разбирать готовый текст агента вместо повторного заполнения формы.
Добавлены правила для примеров:

- `Раменское`;
- `Марина контора`.

Для «Марина контора» автоматически:

- 4 человека → `Откат 1000 ₽`;
- 6 человек → `Откат 1500 ₽`.

Ненужные позиции (гроб, ручки, постель, лента, катафалк и т. п.) в карточку
бригады не переносятся.

## Экран приложения

Нижнее меню:

- **Заказы** — даты, частные/ГБУ, расстановка;
- **Готовность** — официальный срез 15:30 и списки;
- **Сотрудники** — рост, группа, авто;
- **Контроль** — неукомплектованные заказы, не отписавшиеся, загрузка.

## Безопасность

Mini App проверяет `Telegram.WebApp.initData` на сервере и после этого сверяет Telegram ID.
Доступ получают только ID из `ALLOWED_TELEGRAM_IDS`.

То есть ссылку на Mini App можно узнать, но посторонний человек в диспетчерскую не войдёт.

## Развёртывание на Railway

### 1. Отдельный GitHub репозиторий

Создайте, например:

```text
LEGION-dispatcher
```

Загрузите туда содержимое этого архива.

### 2. Railway

Создайте новый сервис из этого GitHub-репозитория.

`Dockerfile` уже готов.

### 3. PostgreSQL

В том же Railway Project добавьте PostgreSQL.

В Variables Mini App создайте `DATABASE_URL` как reference на `Postgres.DATABASE_URL`.

Для Mini App SQLite/Volume не нужен — основная база будет PostgreSQL.

### 4. Variables Mini App

```text
BOT_TOKEN=<токен вашего существующего бота>
ALLOWED_TELEGRAM_IDS=<ваш Telegram ID>,<ID помощника 1>,<ID помощника 2>
BOT_API_KEY=<длинный случайный секрет>
BOT_TIMEZONE=Europe/Moscow
DATABASE_URL=<Railway Postgres reference>
DEV_MODE=0
```

`BOT_API_KEY` должен быть одинаковым в сервисе бота и Mini App.

### 5. Public Domain

У сервиса Mini App в Railway создайте публичный HTTPS-домен.

Например:

```text
https://legion-dispatcher-production.up.railway.app
```

### 6. Кнопка «Диспетчерская» только владельцу и помощникам

Для вашего сценария лучше **не делать глобальную кнопку для всех пользователей**.
В текущем `bot.py` показывайте WebApp-кнопку `📋 Диспетчерская` только вашим Telegram ID.
Готовый пример есть в `BOT_INTEGRATION.md`.

Если всё же настраивать Main Mini App через `@BotFather`, backend всё равно не пустит
агентов и бригадиров, потому что доступ проверяется по `ALLOWED_TELEGRAM_IDS`.

### 7. Подключить текущий bot.py

См. файл `BOT_INTEGRATION.md`.

Там есть готовый `dispatcher_client.py` и точки, где текущий бот должен передавать:

- регистрации агентов;
- регистрации сотрудников/бригадиров;
- `готов / не готов / выходной`;
- новые заказы;
- готовые формы агентов;
- подтверждение бригадира.

## Локальная проверка (необязательно)

```bash
pip install -r requirements.txt
export DEV_MODE=1
export ALLOWED_TELEGRAM_IDS=1
export BOT_TOKEN=dummy
export BOT_API_KEY=secret
python seed_demo.py
uvicorn app:app --reload
```

Открыть:

```text
http://127.0.0.1:8000/?dev_uid=1
```

`DEV_MODE=1` никогда не включайте в production.

## Проверка парсеров

```bash
pytest -q
```

В комплекте есть тесты на формы «Раменское» и «Марина контора».
